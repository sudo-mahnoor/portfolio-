How I ship a change

Ready

  1. Every change starts in Git, on GitHub or a self-hosted GitLab, so there is a record of who changed what.

  2. The application is packed into a Docker image, so it runs the same way on staging and production.

  3. GitHub Actions or Azure DevOps runs the build and the tests. A failed check stops the release.

  4. Docker Compose releases it to the server, behind an Nginx reverse proxy with Let's Encrypt SSL.

  5. Prometheus, Grafana, Loki and Uptime Kuma watch SSL expiry, disk, memory, container health and uptime.

  6. PostgreSQL backups run on a schedule, and restores are tested, so a bad day stays recoverable.
